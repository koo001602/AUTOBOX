## 1. 브랜치 전략

오토박스는 **모노레포(monorepo)** 구조를 사용하며, 파트별 개발 독립성과 배포 안정성을 위해 브랜치를 분리합니다.

### 1.1 기본 브랜치 구조

```
master                    ← 최종 배포 (직접 작업 금지)
  ├── Frontend            ← 프론트엔드 파트 브랜치
  ├── Backend             ← 백엔드 파트 브랜치
  ├── AI                  ← AI 파트 브랜치
  ├── Embedded            ← 임베디드 파트 브랜치
  └── Develop             ← 통합 개발 & 배포 기준 브랜치
```

| 브랜치 | 용도 |
|--------|------|
| `master` | 최종 배포 기준 (직접 작업 금지) |
| `Develop` | 모든 파트가 병합되는 통합 브랜치 |
| `Frontend` / `Backend` / `AI` / `Embedded` | 각 파트별 안정 브랜치 |

### 1.2 기능 브랜치 규칙

**형식:** `파트/feat/설명` 또는 `파트/fix/설명`

```bash
# 예시
Frontend/feat/login-page
Backend/fix/token-refresh
AI/feat/image-classification
Embedded/feat/motor-control
```

> 기능 브랜치는 항상 **해당 파트 브랜치에서 분기**합니다.

## 2. 개발 환경 세팅

### 2.1 일반 개발 환경 (PC)

#### Step 1: 저장소 클론

```bash
git clone <REPO_URL>
cd <REPO_NAME>
```

#### Step 2: 파트 브랜치 체크아웃

```bash
# 프론트엔드
git checkout Frontend

# 백엔드
git checkout Backend

# AI
git checkout AI

# 임베디드
git checkout Embedded
```

#### Step 3: 기능 브랜치 생성

```bash
# 예시: 프론트엔드 로그인 기능 개발
git checkout -b Frontend/feat/login-page
```

### 2.2 파트별 의존성 설치

#### Frontend (폴더명: `Frontend`)

```bash
cd Frontend
npm install
npm run dev
```

#### Backend (폴더명: `Backend`)

```bash
cd Backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

#### AI (폴더명: `AI`)

```bash
cd AI
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

#### Embedded (폴더명: `Embedded`)

```bash
cd Embedded/raspberry-pi
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 3. 개발 워크플로우

### 3.1 전체 흐름도

```
1. 파트 브랜치 체크아웃
      ↓
2. 기능 브랜치 생성
      ↓
3. 개발 & 커밋
      ↓
4. 파트 브랜치로 머지
      ↓
5. Develop 브랜치로 MR(PR) 생성
      ↓
6. 코드 리뷰 & Approve
      ↓
7. 머지 완료
```

### 3.2 상세 단계

#### Step 1: 최신 코드 동기화

```bash
git checkout Frontend          # 해당 파트 브랜치로 이동
git pull origin Frontend       # 최신 코드 가져오기
```

#### Step 2: 기능 브랜치 생성

```bash
git checkout -b Frontend/feat/login-page
```

#### Step 3: 개발 & 커밋

```bash
# 변경사항 확인
git status

# 스테이징
git add .

# 커밋 (컨벤션 준수)
git commit -m "[FE] feat: 로그인 페이지 구현"
```

#### Step 4: 기능 브랜치 푸시

```bash
git push origin Frontend/feat/login-page
```

#### Step 5: MR(PR) 생성

- GitLab/GitHub에서 MR(PR) 생성
- 대상: `Frontend/feat/login-page` → `Frontend`
- 이후: `Frontend` → `Develop`

## 4. 커밋 컨벤션

### 4.1 커밋 메시지 형식

```
[파트] type: 설명
```

### 4.2 파트 코드

| 파트 코드 | 설명 |
|-----------|------|
| `FE` | Frontend |
| `BE` | Backend |
| `AI` | AI |
| `EM` | Embedded |

### 4.3 Type 종류

| Type | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README 등) |
| `refactor` | 코드 리팩토링 (기능 변경 없이 코드 개선) |
| `chore` | 설정, 빌드, 패키지 등 기타 작업 |
| `style` | 코드 포맷팅, 세미콜론 누락 등 |
| `test` | 테스트 코드 추가/수정 |

### 4.4 커밋 예시

```bash
# 좋은 예시
git commit -m "[FE] feat: 로그인 페이지 구현"
git commit -m "[BE] fix: 토큰 만료 처리 수정"
git commit -m "[AI] feat: 이미지 분류 모델 추가"
git commit -m "[EM] fix: 초음파 센서 거리 오차 수정"
git commit -m "[FE] docs: README 업데이트"
git commit -m "[BE] refactor: 인증 로직 분리"

# 나쁜 예시
git commit -m "로그인 구현"           # 파트, type 없음
git commit -m "[FE] 로그인 구현"      # type 없음
git commit -m "feat: 로그인 구현"     # 파트 없음
```

## 5. MR(PR) 및 머지 규칙

### 5.1 MR(PR) 제목 형식

```
[파트] type: 작업 내용
```

**예시:**

```
[FE] feat: 로그인/회원가입 페이지 구현
[BE] fix: 토큰 갱신 로직 수정
[AI] feat: 객체 탐지 모델 통합
[EM] feat: 모터 제어 로직 구현
```

### 5.2 MR(PR) 병합 규칙

| 규칙 | 설명 |
|------|------|
| Approve | **최소 1명 이상** 코드 리뷰 승인 필요 |
| Conflict | 충돌 해결 후 MR 요청 |
| Self-review | MR 생성 전 본인 코드 리뷰 필수 |

### 5.3 병합 흐름

```
기능 브랜치 → 파트 브랜치 → Develop → master
```

**예시:**

```
Frontend/feat/login-page → Frontend → Develop → master
```

### 5.4 머지 후 브랜치 삭제 규칙

| 브랜치 유형 | 예시 | 머지 후 삭제 |
|-------------|------|--------------|
| **파트 브랜치** | `Frontend`, `Backend`, `AI`, `Embedded` | 삭제 안 함 (계속 유지) |
| **기능 브랜치** | `Frontend/feat/login`, `Embedded/fix/sensor` | 삭제 (머지 완료 후) |

```bash
# 기능 브랜치 머지 후 삭제 방법

# 로컬 브랜치 삭제
git branch -d Frontend/feat/login-page

# 원격 브랜치 삭제
git push origin --delete Frontend/feat/login-page
```

> 파트 브랜치(`Embedded`, `Frontend` 등)는 **절대 삭제하지 않습니다.**  
> 기능 브랜치(`Embedded/feat/motor-control` 등)만 머지 완료 후 삭제합니다.

## 6. 주의사항

### 6.1 절대 금지 사항

| 금지 | 이유 |
|------|------|
| `master`, 파트 브랜치에 직접 push | 코드 품질 관리 |
| API Key, Token 등 민감 정보 커밋 | 보안 |
| `node_modules`, `.venv`, `dist` 커밋 | 저장소 용량 |

### 6.2 필수 .gitignore 항목

```gitignore
# Dependencies
node_modules/
.venv/

# Build
dist/
build/
__pycache__/
*.pyc

# Environment
.env
.env.local

# Logs
*.log

# IDE
.vscode/
.idea/
```

## 7. 부록: 임베디드 전용 가이드

임베디드 장비(라즈베리파이 / Jetson)에서는 저장소 전체가 아닌 **Embedded 폴더와 docs 폴더만** 필요합니다.

### 7.1 Sparse Checkout 방식 (권장)

이 방식을 사용하면 `Embedded/`와 `docs/` 폴더만 클론됩니다.

```bash
# 1. 부분 클론
git clone --filter=blob:none --no-checkout <REPO_URL>
cd <REPO_NAME>

# 2. Sparse checkout 초기화
git sparse-checkout init --cone

# 3. Embedded + docs 폴더 지정
git sparse-checkout set Embedded docs

# 4. Develop 브랜치 체크아웃
git checkout Develop

# 5. 기능 브랜치 생성
git checkout -b Embedded/feat/기능명
```

**결과:**

```
<REPO_NAME>/
├── Embedded/          ← 임베디드 코드
│   └── raspberry-pi/
│       ├── mqtt_client.py
│       ├── mqtt_publisher.py
│       └── ...
└── docs/              ← 문서
    ├── Contributing.md
    └── ...
```

### 7.2 임베디드 개발 한 줄 요약

```bash
git clone --filter=blob:none --no-checkout <REPO_URL> && cd <REPO> && git sparse-checkout init --cone && git sparse-checkout set Embedded docs && git checkout Develop && git checkout -b Embedded/feat/기능명
```

### 7.3 자주 하는 실수

| 실수 | 해결 |
|------|------|
| `git clone` 전체 실행 | Sparse Checkout 사용 |
| `Develop`에 직접 커밋 | `Embedded/feat/*` 브랜치 사용 |
| `.venv`, `__pycache__` 커밋 | `.gitignore` 확인 |

## Quick Reference (빠른 참조)

### git checkout vs git checkout -b 차이

| 명령어 | 설명 | 사용 시점 |
|--------|------|-----------|
| `git checkout <브랜치명>` | **기존 브랜치로 이동** | 이미 존재하는 브랜치로 전환할 때 |
| `git checkout -b <브랜치명>` | **새 브랜치 생성 + 이동** | 새로운 기능 브랜치를 만들 때 |

```bash
# 예시: 기존 Frontend 브랜치로 이동
git checkout Frontend
# → Frontend 브랜치가 이미 존재해야 함
# → 없으면 에러 발생

# 예시: 새로운 기능 브랜치 생성 및 이동
git checkout -b Frontend/feat/login-page
# → Frontend/feat/login-page 브랜치를 새로 만들고 바로 이동
# → 현재 브랜치를 기준으로 분기됨
```

**참고:** `-b` 옵션은 `branch`의 약자로, 브랜치 생성과 이동을 한 번에 수행합니다.

```bash
# 아래 두 명령은 동일한 결과
git checkout -b Frontend/feat/login-page

# ↓ 위 명령은 아래 두 줄을 합친 것
git branch Frontend/feat/login-page    # 브랜치 생성
git checkout Frontend/feat/login-page  # 브랜치 이동
```
